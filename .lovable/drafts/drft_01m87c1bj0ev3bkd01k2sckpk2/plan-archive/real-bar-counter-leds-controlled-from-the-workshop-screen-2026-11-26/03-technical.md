## Technical details
- **Database**: `led_devices` (id, name, hashed device token, group_count, direction, provisional flag); `led_desired` (device_id, schema_version, revision bigint, state jsonb, request_id, updated_at); `led_reported` (applied_revision, boot_id, controller_version, status, capabilities, last_error, heartbeat_at); `led_presets`. RLS turns on with no anon or authenticated policies, so all access goes through server functions.
- **Screen server functions** (public): `getLedState`, plus `setLedState({ baseRevision, requestId, state })`. The new state is checked with zod, then a single SQL function applies it atomically: it bumps the revision, removes duplicate request IDs, and returns a stale conflict when `baseRevision` is older than the current one. Off passes `force` so it wins over older pending edits. There are also preset CRUD and calibration requests.
- **Pi endpoints**: `/api/public/led/device/{poll,report}` with a bearer device token, compared against its hash. A long-poll of about 25s gives near-instant pickup, and the same request also acts as the reconciliation check. Report is accepted only for that device. No service key ever reaches the browser.
- **Screen sync**: TanStack Query polls every 3s while the pop-up is open and every 15s when it's closed. Slider changes wait 200ms before sending, and the last value is sent when you let go. A fresh read from the server always replaces any locally cached state.
- **Python package** (downloadable zip under `/pi/`): `controller.py` uses a network thread with a queue and a render thread at about 30fps with monotonic time, and caps the frame rate based on how long one frame takes to transmit at 800kHz. It keeps the rainbow logic (48-group repeat, 8s breathing). Settings are validated against a schema and applied between frames, with crossfades and the animation phase preserved. The last state is cached atomically with tmp+rename, and it starts off when no cache exists. SIGTERM sends black. A flock lock file prevents two copies from running. `ledctl off` gives a local Off. Also included: `requirements.txt`, `led-controller.service`, `install.sh` (backs up the old script and services, then disables `led-strip-rainbow` and `led-strip-white`), `ROLLBACK.md`, `CONTRACT.md` with example payloads, and `simulator.py`.
- **Device enrollment**: a Setup button generates a token and shows it once. The token is saved on the Pi in `/etc/led-controller/token` with mode 0600, and it can be revoked or rotated.
- **Tests**: revision and stale-edit handling, duplicate request IDs, Off beating debounce, invalid payloads, rejecting unauthorized device reports, "Applied" shown only after a report, and on the Python side, cache restore after reboot plus ignoring older revisions.
- **Deployment and commissioning docs** for Codex, each step marked as either a software test or a visual hardware check. Kiosk steps assume the Pi drives the monitor. The Pi isn't touched from here.
